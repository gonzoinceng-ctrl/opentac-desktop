## 2026-11-03 — Phase 0 validation: what the live checkout and live services changed

Validation ran as parallel investigations against upstream HEAD `48146f8e` and the live Ollama / OpenRouter / xAI / GitHub docs. Facts that override the brief:

- **Launcher stdin watchdog (scaffold bug, confirmed by running it).** The scaffold launcher exited within ~2 s with "stdin closed" whenever stdin was `/dev/null` or a closed descriptor, so it never served HTTP when run from a non-interactive shell. Fixed: the watchdog only arms when fd 0 is a FIFO or socket (what Electron's `stdio: 'pipe'` gives us), and `OPENTAC_NO_STDIN_WATCHDOG=1` disables it for tests. The shell **must** spawn the launcher with stdin as a pipe and hold it open for the life of the server; an integration test pins this.
- **Upstream runs cleanly under Node 24.22.2.** `npm ci` (`PUPPETEER_SKIP_DOWNLOAD=1`) installs 223 packages, 409 MB. Cold start to HTTP 200 is ~0.5 s with a warm Vite cache, warm start ~0.4 s. The ready line is `[OpenTac] Ready at http://127.0.0.1:PORT/` and it is printed **after** Vite's own `➜  Local: http://127.0.0.1:PORT/` line, which contains the same URL; readiness parsing matches the `[OpenTac] Ready at ` prefix only. Stdout carries everything; stderr was empty. The checkout writes `.gev-cache/` into `process.cwd()`, so cwd must be the writable checkout.
- **Keyless smoke endpoint for the gate:** `GET /api/celestrak/stations` returns live TLE text with no keys (`server/providers/space/celestrak.js`). `/api/setup/status` answers 200 with or without an `Origin` header and 403 for a foreign origin.
- **npm 11 `allowScripts`.** npm 11.19 warns about install scripts not on an allow-list but still runs the engine's install fine (esbuild uses its optional platform package). The shell's own `package.json` carries `allowScripts` approvals for dugite, esbuild and electron-winstaller so CI is quiet and deterministic. The InstallManager must tolerate these warnings on stderr.
- **HUD summary contract has drifted (07-AI-PROVIDERS.md).** `server/providers/openai/hud-summary.js` now sends `max_output_tokens: 200` (not 100) and a **strict JSON schema** via `text.format` (`{summary, feedState}`); the reply text must itself be JSON or `parseHudSummaryReply` yields an empty summary. `toFiveWordHudSummary` does not exist; it is `toHudSummary` with an 80-character cap. `extractOpenAiResponseText` accepts either top-level `output_text` or `output[].content[].text|output_text`; emit exactly one message item with one content part, never several (they are joined with spaces and break `JSON.parse`).
- **The handler short-circuits before `fetch` when `OPENAI_API_KEY` is empty** (`keylessHudSummaryResponse`). For a non-OpenAI summary provider the launcher must inject a placeholder `OPENAI_API_KEY` **only if** the checkout's `.env` does not already define one (so a real key for voice still loads), and the gateway must drop the incoming `Authorization` header and use its own backend key. The interceptor matches only `POST https://api.openai.com/v1/responses`; the Realtime `client_secrets` URL goes through the same global `fetch` and is never rewritten.
- **Ollama 0.40, OpenRouter and xAI all serve the Responses API natively** (`/v1/responses`; xAI marks chat-completions as legacy). Verified live against Ollama (`qwen3:8b`): the upstream request shape, including `text.format` json_schema, is honoured. The gateway therefore becomes a **pass-through with origin, key and model rewrite** for these three, plus a floor on `max_output_tokens` and `reasoning` forced off; the chat-completions translation stays only as a fallback adapter. Thinking models (`qwen3:8b`) spend the whole token budget on reasoning and return empty content unless reasoning is disabled; the Preferences "Test" button reports `finish_reason`/empty output plainly.
- **xAI now has a WebSocket realtime voice API** (`wss://api.x.ai/v1/realtime`, "compatible with the OpenAI Realtime API"). Upstream's voice is WebRTC (`/v1/realtime/calls`), so it is still not a drop-in; the brief's "no realtime voice" statement is simply stale and the UI copy says "voice control uses OpenAI or Gemini" without claiming xAI cannot.

## 2026-11-03 — Staged update pipeline: design corrections to 08-STAGED-UPDATES.md

The gate-and-canary shape is kept. These mechanics change because GitHub would not run 08 as written:

1. **Mirror is a plain public repository, not a fork**, named `opentac-engine`. Forks start with scheduled workflows disabled and cannot change visibility; "zero engine commits of its own" is enforced by CI with `git merge-base --is-ancestor <stable> <live upstream main>` against the real upstream remote, not fork status.
2. **The workflows live on the mirror's default branch.** GitHub only runs `schedule`, `repository_dispatch` and the "Run workflow" button from the default branch. The orphan branch `opentac-ci` (workflows, `ci/contracts.mjs`, tag manifest, `RELEASES.md`) **is** the default branch; engine refs (`upstream-main`, `candidate`, `stable`, `v*`, `stable-*`) are ordinary non-default refs. No branch named `main` is ever pushed to the mirror, so upstream's own `ci.yml` cannot fire there.
3. **Ref pushes use a dedicated token, not `GITHUB_TOKEN`.** Upstream edits `.github/workflows/ci.yml` regularly (twice between v0.3.0 and HEAD) and `GITHUB_TOKEN` has no `workflows` scope, so the first fast-forward past v0.3.0 would be rejected. A fine-grained PAT or GitHub App token with Contents + Workflows + Issues write on the mirror (secret `ENGINE_PUSH_TOKEN`) does every push and every cross-repo dispatch. Every workflow declares `permissions:` explicitly.
4. **Intake policy.** The owner asked for a weekly pull of all new upstream commits, and upstream tags only roughly monthly, so `INTAKE_POLICY` defaults to `main` (tip of `upstream-main` each Sunday), gated and canaried exactly as before. `tags` remains available and, when chosen and no newer tag exists, intake is a **no-op that says so**, never a silent fallback to main.
5. **`candidate` only moves after the gate is green.** The gate receives an explicit SHA, never the ref name. The per-SHA verdict is recorded in the canary issue body as JSON (`{sha, upstreamTag, readyAt, gateRunUrl, minShell}`) and as a git note under `refs/notes/gate`. `promote` promotes the SHA recorded in the issue, re-checks `hold`/`reject` labels immediately before pushing, requires `readyAt + 72 h`, and runs under `concurrency: engine-refs` with intake. A newer intake closes the old canary issue as `superseded` and restarts the clock.
6. **Promotion tags** are `stable-YYYY.MM.DD` with a `-N` suffix when a day has more than one; the app orders them by commit ancestry, not name. The annotation carries the upstream tag (if any), commit range, gate run URL, canary days, `minShell` and `severity: normal|security`.
7. **Tag drift:** `opentac-ci/manifest/tags.json` records object and peeled SHA for every upstream tag mirrored; `watch` compares `git ls-remote --tags` against it before fetching and fails loudly on any change. A tag ruleset on the mirror forbids updating or deleting `v*` and `stable-*`.
8. **Runners:** contract checks and upstream's own `npm test`/`build` on `ubuntu-latest`; the Electron smoke on `macos-15` (arm64) and `macos-15-intel` (x64). `macos-latest` is arm64-only and `macos-14` was retired on 2026-11-02. Public repos make these free.
9. **Cross-repo triggers:** the site rebuild in the app repo runs on a 6-hourly schedule plus `workflow_dispatch`, polling the mirror's newest `stable-*` tag; `promote` additionally fires a `repository_dispatch` with `ENGINE_PUSH_TOKEN`. Release-published site rebuilds depend on the owner publishing the draft by hand, which 05 already requires.
10. **Shell/engine compatibility contract:** each `stable-*` annotation carries `minShell`; the shell refuses an engine update whose `minShell` exceeds its own version and offers "Update OpenTac first". The gate smoke runs against the latest released shell and app `main`.
11. **Delivery latency:** in addition to the launch check, the shell re-checks every 6 h while running, on `powerMonitor` resume and on window focus (rate-limited), using `git ls-remote` (no API quota). A `severity: security` promotion bypasses `skippedCommit`.
12. **Shell-side weekly maintenance** in the app repo: a scheduled job compares `scripts/node-version.json` against nodejs.org's 24.x line and Electron 45.x patches and opens an issue/PR; a dead-man check opens an issue if the mirror's `upstream-main` is more than 48 h stale or `watch.yml` is disabled. Node version and checksums move to `scripts/node-version.json` so both repos read one machine-readable file.
13. **Notification noise:** `watch` is silent except on anomalies; intake sends one weekly digest; the Thursday promote message states whether the candidate build was ever launched on the owner's Mac (local marker the candidate-channel app writes and the owner confirms via a `canary-ok` label for the first promotions).

## 2026-11-03 — Foundation modules

- `Channel` is `'stable' | 'candidate' | 'upstream'` (08-STAGED-UPDATES.md §4), not the `'stable' | 'main'` of 03-ARCHITECTURE.md §2; 03 is superseded on this point. `state.json` keeps `schemaVersion: 1`; the AI preference (`provider`, `model`, `ollamaHost`) lives there while provider keys live in Keychain.
- Log redaction treats a `KEY=VALUE` assignment as secret only when the key **ends** in `API_KEY`, `KEY`, `TOKEN`, `SECRET`, `PASSWORD` or `PASS` (whole-word suffix), so `max_tokens=200` in a Vite or upstream log line is not blanked. Token-shaped values (OpenAI, Google, GitHub, OpenRouter, xAI, JWTs, Bearer headers, URL credentials) are redacted regardless of context.
- `saveState` is atomic (tmp + fsync + rename, mode 0600) but not serialised; the controller is the single writer and awaits each save, which is the invariant that keeps this safe.

## 2026-11-03 — Phase 0 validation, round two (brief consistency, Electron 45 APIs, upstream contracts)

Every blocker/high finding below survived an adversarial refutation pass. Each one is now reflected in the repo.

**Packaging and signing**
- `com.apple.security.cs.disable-library-validation` is **on by default** (not "only if needed"): the engine's `npm ci` output contains ad-hoc, linker-signed native addons (rollup, fsevents, sharp/libvips) that a hardened-runtime Node cannot `dlopen` otherwise. Verified experimentally. Phase 5 acceptance includes `process.dlopen` of those addons from the signed bundle on a clean Mac.
- The scaffold's `extraResources` filter `lib/node_modules/npm/**` silently dropped npm: electron-builder adds `!**/node_modules/**` to any pattern that mentions `node_modules`. Filter is now `["bin/**", "lib/**", "LICENSE"]`; a pack-time test asserts `Resources/node/lib/node_modules/npm/bin/npm-cli.js` exists.
- The bundled Node now also carries `bin/npm` and `bin/npx` (symlinks from the official tarball): upstream's `setup-doctor.mjs` runs `npm --version` via PATH and reports "not ready" without them.
- Minimum macOS is **13.5** (Electron 45 requires 13; the official Node 24 binaries are built for 13.5). Website copy says "macOS 13.5 or later".
- dugite's postinstall downloads git for **one** architecture, so building both arches from one `node_modules` ships arm64 git inside the x64 app. The release workflow builds each arch in its own job on a native runner (`macos-15` arm64, `macos-15-intel` x64), asserts `file` on `Resources/node/bin/node` and the unpacked `git`, and a final job **merges the two `latest-mac.yml` files** before the draft is published (two jobs otherwise overwrite each other's and electron-updater loses one arch). Default zip names (`OpenTac-<v>-mac.zip`, `OpenTac-<v>-arm64-mac.zip`) are kept because MacUpdater matches on the `arm64` substring.
- `mac.notarize` is a boolean; a missing `APPLE_*` credential only logs a warning and the build stays green. CI writes the `.p8` secret to a file, exports its **path** as `APPLE_API_KEY`, and fails on `xcrun stapler validate` / `spctl -a -vv -t install`. The release workflow needs `GH_TOKEN` with `contents: write` for the draft upload.
- Electron fuses are set (`runAsNode` off, cookie encryption on, `NODE_OPTIONS` off, CLI inspect off, asar integrity on, only-load-from-asar). Playwright's `_electron` needs `enableNodeCliInspectArguments`; the e2e suite runs against an unpackaged build, so the fuse stays off in releases.
- Git Credential Manager (.NET, ~70 MB per arch, 219 DLLs) is excluded from the dugite tree in the bundle; no credential helper is ever configured.
- Reproducibility is "same file list and Mach-O arch", not byte-identical bundles (electron-builder is not deterministic).

**Electron main, preload, renderer**
- Main is ESM, but **never `await app.whenReady()` at top level** (it never resolves; the ready event waits for module evaluation). Scheme registration and command-line switches run synchronously at top level; everything else inside `app.whenReady().then(...)`.
- `electron-updater` is CJS with a getter-defined `autoUpdater`: use `import updater from 'electron-updater'; const { autoUpdater } = updater;`. A named import crashes at load.
- Sandboxed preloads cannot be ESM: each is bundled by esbuild to a single `.cjs` (`external: ['electron']`, no `node:` builtins). `src/shared` must stay free of Node builtins so it can be bundled into preloads.
- `will-navigate`, `will-redirect`, `will-frame-navigate` and `setWindowOpenHandler` live on `webContents`, not `BrowserWindow`. Upstream calls `window.open(url, '_blank')` in several places, so the open handler routes `https:` to `shell.openExternal` and denies everything else.
- Permissions: WebUSB goes through **`setPermissionCheckHandler`** (must return true for `usb` on the engine origin); the request handler never sees it. `select-usb-device` must call `event.preventDefault()` and persist the full device identity (vendor, product, productName, serialNumber: dual-channel RTL-SDR boards share a serial). `media` is checked with `mediaTypes` (audio only); `display-capture` is denied; `geolocation` is denied cleanly (no macOS provider); `clipboard-sanitized-write` and `fullscreen` allowed for the engine origin only.
- `safeStorage`: use the async API (`encryptStringAsync` / `decryptStringAsync`, sync variants removed in Electron 46), honour `shouldReEncrypt`, and store the ciphertext in `<dataDir>/secrets.json` (0600). "Keychain" in the brief means the key that protects that file lives in Keychain.
- Port is **pinned per install**: browser state (layers, favourites, SDR choice, mic grant) is keyed by origin, so silently moving from 4173 to 4174 would appear to wipe it. If the saved port is busy at launch the ERROR panel offers Retry or "Use a different port (resets saved layers and permissions)".
- Setup window is resizable (default 760×560, min 600×440); the update disclosure, crash view, error view and Preferences all live there. The main-window preload stays minimal (versions, openExternal) and is not used by upstream code.
- Single-instance lock, Dock reopen, `window-all-closed` (keep the server running until explicit Quit on macOS), and `powerMonitor` resume are specified in `docs/SHELL-DESIGN.md`.

**Engine contract drift found in the live checkout**
- The client is now Vue 3 + Pinia + vue-i18n; `@vitejs/plugin-vue` is a devDependency needed at runtime (one more reason `npm ci` must never use `--omit=dev`).
- `pinokio-start.mjs` no longer contains the literal `await import("vite")` (it is a default parameter of `loadViteFromCanonicalRoot`); the gate's contract check asserts ordering structurally, not by that literal.
- Keyless endpoints that exist: `/api/setup/status` (expect `store: 'env-file'`), `/api/cctv/sources`, `/api/celestrak/<group>`, `/api/flights`. `/api/satellites` and `/api/opensky` do not exist.
- Upstream's `key-setup.js` snapshots every provider key present in `process.env` **at boot** and marks those rows "external" (read-only, 409 on save). So the engine child env must contain none of `GOOGLE_MAPS_API_KEY, GOOGLE_MAPS_SERVER_API_KEY, OPENAI_API_KEY, GEMINI_API_KEY, AISSTREAM_API_KEY, FIRMS_MAP_KEY, TOMTOM_API_KEY, CESIUM_ION_TOKEN, OPENSKY_CLIENT_ID, OPENSKY_CLIENT_SECRET, MAPILLARY_CLIENT_TOKEN, LL2_API_TOKEN` (the clean-env builder guarantees this), **except** the deliberate `OPENAI_API_KEY` placeholder when a non-OpenAI summary provider is active and `.env` has no OpenAI key. Consequence, stated in Preferences: while Ollama/OpenRouter/xAI summaries are on, the engine's OpenAI key row is locked and voice needs a real OpenAI/Gemini key entered **before** switching, or the user switches back to OpenAI first. Any `PINOKIO_SHARE_*` variable in the child env disables the panel (403), so none is ever passed.
- The AI gateway is an unauthenticated local endpoint by the brief's design; it now requires a per-launch random token (`OPENTAC_AI_GATEWAY_TOKEN`, sent by the launcher's interceptor as `x-opentac-gateway-token`), strips the incoming `Authorization`, binds 127.0.0.1 only and caps bodies at 1 MB.
- Vite with `strictPort` reports "Port N is already in use" (no `EADDRINUSE` text); the launcher matches both.
- `OPENTAC_FAIL_START_ONCE` has once-semantics in the **shell**: the controller passes it for exactly one spawn and strips it afterwards, so the rollback start can succeed.
- Update order: **stop the server first**, then checkout, then install, then start. If `npm ci` fails after the checkout, roll the checkout back and reinstall from the warm npm cache; the residual risk (cache miss while offline) is shown as an actionable error, not hidden.
- `/mcp` is live on the engine port for any local process; the privacy copy says so.
- Upstream's `LICENSE` carries a note that the MIT grant covers **source code only**: submarine-cable data is CC BY-NC-SA, Bhote Koshi imagery CC BY-NC, OSM extracts ODbL. The full file is reproduced verbatim in `THIRD_PARTY_NOTICES.md`, `/licenses` and About; OpenTac is distributed as a non-commercial project unless the owner decides otherwise.

## 2026-11-03 — USB productName persistence limitation

The shell remembers `productName` for each WebUSB pick in memory and matches on it (dual-channel RTL-SDR boards share vendor, product and serial), so within a session picking one channel does not grant its sibling. `UsbDeviceId` in `src/shared/types.ts` and `readUsbDevices` in `src/main/state.ts` have no `productName` field, so the name is dropped when `state.json` is loaded and the match falls back to vendor, product and serial after a restart. Follow-up for the state owner: add `productName?: string` to `UsbDeviceId` and read it in `readUsbDevices`; no change is needed in the electron layer.

## 2026-11-03 — Shell layer implementation notes (controller, windows, IPC, renderer, e2e)

Final verification: build and both typechecks clean; 588 unit/integration tests; 5/5 Playwright `_electron` tests (boot to RUNNING, setup window hidden, external links suppressed, menu-driven engine update disclosure, clean quit); unsigned `npm run pack` contains npm-cli.js, an arm64 git and the launcher; a 20 s real launch against the fixture mirror reaches RUNNING and shuts down cleanly. Deviations from `docs/SHELL-DESIGN.md`:

1. Two extra transitions: `INSTALLING → ROLLING_BACK` (a failed `npm ci` after the checkout moved must roll back) and `RESTARTING → INSTALLING` (Reinstall Dependencies from a running engine). Every edge into `ROLLING_BACK` is guarded by the presence of `rollbackCommit`.
2. `OPENTAC_FAIL_START_ONCE` is consumed by the first `server.start()` made while a rollback marker exists (a post-update start, or a boot resuming an interrupted update), then stripped; a plain boot never consumes it. A literal "first start ever" would have made the flag useless for the rollback drill.
3. A user `rollback` action from ERROR or CRASHED passes through STARTING then ROLLING_BACK (no direct ERROR → ROLLING_BACK edge).
4. After a rollback caused by a failed update, `skippedCommit` is set to the attempted commit so background checks do not re-announce it; interactive checks and `security` releases still do.
5. Any change of `state.ai.provider` restarts the engine (RESTARTING) with a fresh gateway and token; if it happens outside RUNNING it is applied on the next return to RUNNING.
6. All automatic checks (launch, 6 h, resume, focus) are gated on `updateCheckOnLaunch` and rate-limited by `lastUpdateCheck` with a 60 s tolerance; `lastUpdateCheck` is not stamped on an offline result.
7. A gateway that fails to start degrades to "no gateway" with a notice rather than ERROR.
8. The < 2 GB disk check is enforced only when a clone or install is actually needed; otherwise it is logged.
9. A checkout with `installedCommit` null (clone that never installed) is re-checked-out to the channel target at boot, so a retry after a half-done first run works.
10. `resetCheckout` (ERROR only) backs up the engine `.env` to `<dataDir>/env.backup` (0600), deletes and re-clones, restores `.env`, removes the backup.
11. `runInstall` clears `installedLockHash`/`installedNodeVersion` before `npm ci`, so a failed or aborted install leaves `needsInstall()` true and a rollback reinstalls.
12. TAG_DRIFT during a check is surfaced as an ERROR that can be retried, with the engine left running (the tree is untouched).
13. A crash while CHECKING or DISCLOSING is handled like a crash while RUNNING.
14. Browser-state note: `OPENTAC_E2E_NO_EXTERNAL=1` makes `shell.openExternal` log instead of open (unpackaged only); used by the e2e suite.

## 2026-11-03 — Settings screen: the shell now writes engine settings into the engine `.env`

The owner asked for one settings screen for every API key and setting the project can use (Preferences, section 14 of `docs/SHELL-DESIGN.md`). Consequences, in order of how much they deviate from earlier decisions:

1. **The shell now writes non-registry settings to the engine `.env`.** Until now the brief and this file said the shell never touches the engine `.env` (it only backs it up and restores it around a re-download, and reads key *names* to decide the placeholder). The settings screen needs voice models, rate limits, data-feed options and the CCTV pack switches, none of which the engine's own endpoint accepts (it writes only its 12 registry variables), so OpenTac writes them itself. Justification: the owner's request, and upstream's own writer is line-preserving (`upsertDotenvValues`: replace the last active assignment, else uncomment the last commented one, else append; clear = comment out; every other line survives byte for byte), so `envSettings.ts` mirrors it exactly and keeps the same guarantees: atomic tmp + fsync + rename, mode 0600, no write through a symlink, and an unreadable file aborts instead of being overwritten. It **never** writes the 12 registry variables (the engine's endpoint owns those, including its externally-managed rule), `HOST`, `PORT`, `GEV_ALLOWED_HOSTS`, `GEV_KEY_SETUP_TRUSTED_PEERS`, `GEV_EMBED_FRAME_ANCESTORS` or `VITE_*`. Values are validated per type and refuse control characters and the dotenv metacharacters, so what is written is what Node's `parseEnv` and Vite's expansion read back. Still true: the shell **never reads or logs a key value**. It reads names (`envFileKeys`) and, for settings, the non-secret values it manages; secret-typed settings (`ONTARIO_511_API_KEY`, which is not in upstream's registry, so only the shell can store it) are reported as set/unset and never returned; logs carry setting names only.
2. **Engine keys go through the engine's own endpoint.** `engineKeys.ts` calls `GET /api/setup/status` and `POST /api/setup/keys` with the exact local `Origin` upstream's gate requires. The list shown is whatever the engine reports, so it tracks engine updates; the static catalogue is only a fallback and supplies the one row the engine hides (`google-maps-server`, `hidden: true`), which therefore makes 11 rows with the 10 the status lists. The engine restarts itself ~250 ms after a save and the child never exits, so the controller makes no phase change for it; it updates the row optimistically and polls quietly. The 409 `external` refusal and the OpenAI placeholder are shown as **Locked** with the explanation from "Engine contract drift" above; the controller refuses a locked row before asking the engine.
3. **Engine settings need a real engine restart.** The engine's in-process `server.restart()` re-runs `standaloneConfig`, but that copies `.env` values into `process.env` only where `process.env[key] === undefined` (`server/standalone/vite.config.js`), so a value changed in `.env` would be ignored by an in-process restart. Settings therefore need a new process: saving a group goes RESTARTING, STARTING, RUNNING. (The engine's own key save works in-process because it also assigns `process.env[name]` directly.)
4. **App settings extend `state.json` additively** (`app` object, schema version stays 1, missing fields take defaults). Proxy and mirror addresses with credentials are refused so `state.json` stays secret-free. The proxy is passed to the engine as `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, `NODE_USE_ENV_PROXY=1` (reserved names in `buildServerEnv`), and to git and npm as the first three through a `proxyEnv()` hook; the clean-env guarantees are otherwise unchanged. The mirror override is read once at launch, so it applies at the next launch; `OPENTAC_ENGINE_REMOTE` still outranks it. `logLevel` is read from `state.json` before the logger exists; `OPENTAC_LOG_LEVEL` outranks it.
5. **Catalogue provenance.** Descriptions and defaults come from upstream `.env.example` at `48146f8e` (a copy lives in `test/fixtures/gev-env-example.txt`; a test fails if a catalogue variable is not in it or a `CCTV_*` variable of it is neither covered nor on the documented exclusion list). Two enums are not spelled out there and are OpenTac's choice: the voice names (the Realtime voices OpenAI documents) and the reasoning efforts (`minimal | low | medium | high`); the engine accepts any string, so if OpenAI adds a value the list needs a one-line change. Settings not offered on purpose: `CCTV_SOURCES_FILE`, `CCTV_SOURCES_JSON`, `CCTV_PREFER_AUSTIN`, `CCTV_FORCE_AUSTIN`, the two Vegvesen sub-switches (advanced source-pack plumbing).


## 2026-11-03: proxy loopback bypass and mirror override scope

When a proxy is set, NO_PROXY for the engine, git and npm always includes 127.0.0.1, localhost and ::1 (appended to the user's list), because Node with NODE_USE_ENV_PROXY would otherwise send the AI gateway token and prompts to the proxy.
